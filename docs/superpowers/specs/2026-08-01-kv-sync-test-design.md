# KV 原视频逐帧同步测试设计

## 目标

验证“视频中的每一帧同时包含一个人物方向和一格屏幕影像，因此可以由鼠标方向直接选择完整视频帧”的实现是否可行。

测试仅验证桌面端同步效果，不修改正式首页，不处理移动端，也不进行背景去除。

## 测试素材

- 唯一视频源：`KV首屏/首屏头部转动效果（需要除背景）.mp4`
- 原始规格：1470 × 630、193 帧、约 8.02 秒
- 测试资源：从视频等序提取全部 193 帧，保留每一帧的完整画面与屏幕影像

## 页面与交互

- 独立路由：`/kv-sync-test`
- 桌面端全屏展示原始视频画面，不使用正式首页的文字、按钮和主体定位逻辑
- 鼠标相对画面中心的方向转换为 0–360° 角度
- 角度经过新视频方向时间轴映射后，直接选择 0–192 中的源帧
- 页面显示当前角度、源帧编号和资源加载进度，便于人工核对
- 鼠标停止后保持当前完整帧；人物方向和屏幕影像不会被拆开或单独播放

## 技术结构

1. 资源脚本从 MP4 提取完整 193 帧并压缩为 WebP，不做降采样和抠图。
2. 纯函数负责“指针角度 → 源帧编号”映射，并通过单元测试固定主要方向。
3. 客户端测试组件预加载帧资源，在 Canvas 中绘制当前完整帧。
4. 正式首页组件、72 帧透明序列和五个按钮逻辑均保持不变。

## 性能与错误处理

- 首帧优先加载，其他帧按与首帧距离逐步预加载。
- 未加载完成时继续显示上一张有效帧，避免白屏或闪烁。
- 单帧加载失败时显示失败计数，但不阻断其他帧。
- 测试页仅用于本地验证，不作为最终生产资源体积方案。

## 验收标准

1. 鼠标绕主体移动时，人物朝向与鼠标方向一致。
2. 屏幕影像始终来自当前人物方向对应的同一源视频帧。
3. 快速移动鼠标时不出现明显白屏、反复闪回或人物与屏幕内容错帧。
4. 访问正式首页时，其现有视觉与交互没有变化。

## 测试

- 单元测试：角度归一化、方向关键帧、首尾帧环绕。
- 资源测试：193 帧完整、命名连续、尺寸为 1470 × 630。
- 浏览器测试：测试路由可访问、Canvas 有有效帧、快速指针输入不产生错误浮层。
