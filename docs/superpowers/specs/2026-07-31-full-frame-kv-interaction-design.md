# Portfolio 2.0 首屏完整画面跟随交互设计

## 目标

使用 `KV首屏/首屏头部转动效果.mp4` 作为首屏主体素材来源。保留视频中已经确定的背景、人物比例与人物位置，不再抠出人物或重新组合背景。鼠标方向变化时，网页显示对应的完整视频帧，形成主体看向鼠标的效果。

本轮同时使用 `KV首屏/WHITE` 与 `KV首屏/BLACK` 中的五组按钮设计稿，替换当前 CSS 绘制的按钮外观。

## 素材与边界

- 视频源：1470×630、约 8 秒、193 帧，时间轴已按围绕主体的方向顺序导出。
- 首次实现使用现有分辨率；在 2K/4K 屏幕上可能被放大。未来替换同构图高分辨率视频时，不修改交互逻辑。
- 输出采用 72 帧完整画面序列。72 帧均匀覆盖视频方向环，在连续感和首屏资源成本之间取平衡。
- 按钮 `WHITE` 为默认态，`BLACK` 为悬停、键盘聚焦及当前预览态。
- 按钮状态直接切换，不使用淡入淡出、缩放或重新排版文字。

## 桌面端交互

1. 浏览器进入首屏后先显示中性正面帧。
2. 以视频画面中机器人头部中心为方向锚点，计算鼠标位置相对锚点的 0—360° 角度。
3. 使用根据源视频实际姿态标定的方向关键帧映射鼠标角度；目标帧直接同步，不增加追帧缓动延迟。
4. Canvas 每次绘制一张完整画面帧，以首屏比例铺设；背景与人物同步变化，不独立移动或缩放人物。
5. 鼠标进入任一按钮时：
   - 按钮立即由 `WHITE` 切换为 `BLACK`；
   - 当前项目的标题、年份与说明立即切换；
   - 五个按钮分别使用五个固定方向帧，从左到右对应左下至右下；离开按钮后恢复自由鼠标跟随。
6. 点击按钮仍沿用现有的“首页主体放大淡出 → 子页面进入”路由过渡。

## 移动端交互

- 默认显示中性正面帧，不自动循环播放。
- 不监听全屏触摸移动，避免与页面纵向滚动冲突。
- 用户触摸或聚焦某个项目按钮时，完整画面切换到该按钮中心对应的方向帧。
- 移动端没有悬停态；触摸后当前预览按钮使用 `BLACK`，其他按钮使用 `WHITE`。

## 素材处理与加载

- 从 MP4 等距抽取 72 张帧图，输出为带编号的 WebP 文件。
- 保持原始 1470×630 画幅，不裁切、不抠图、不改变主体位置。
- 中性帧优先加载并立即显示；其余方向帧随后预加载。
- 页面只在目标帧已经解码后切换，避免出现透明闪帧。
- Canvas 根据设备像素比设置绘制缓冲区，但上限为素材自身有效分辨率，避免无意义放大内存。
- 素材加载失败时保留最近成功显示的帧，不让首屏空白。

## 无障碍与降级

- `prefers-reduced-motion: reduce` 下固定显示中性帧，按钮状态和点击导航仍可用。
- Canvas 保留描述性 `aria-label`；按钮仍使用可聚焦的链接，不用图片替代其可访问名称。
- 键盘聚焦行为与鼠标悬停一致，按 Enter/Space 继续触发原有页面跳转。

## 验收标准

- 桌面端鼠标绕机器人移动一圈时，画面方向连续闭环，不在 0°/360° 处反向跳转。
- 每一帧都包含完整背景与人物，页面中不存在独立的人物抠图层。
- 五个按钮使用提供的设计稿，默认与激活状态无淡入淡出。
- 移动端可正常滑动页面，触摸按钮能切换预览并进入对应页面。
- 现有首页—子页面的进出场动画、五个路由和子页面结构不被破坏。
