# Portfolio 2.0 交互网站设计规格

日期：2026-07-31  
状态：设计已确认，等待书面规格复核  
实施项目：`portfolio-site`

## 1. 核心目标

把 `24559704.png` 中的 Portfolio 2.0 静态首屏，建设成一个具备完整桌面端、移动端、案例子页、URL 分享和连续转场能力的正式作品集网站。

视觉构图以 `24559704.png` 为唯一首屏基准。Todd Hamilton 网站只作为交互机制和工程逻辑参考，不复制其视觉内容、项目名称或高负载 WebGL 资源策略。

第一版优先完成：

1. 五个入口的完整交互链路。
2. 首页与案例页的正式工程结构。
3. 案例内容的可替换占位模板。
4. 大尺寸屏幕清晰度、响应式和无障碍基础能力。

## 2. 首发信息架构

首页保留五个入口：

| 顺序 | 英文标签 | 中文含义 | 路由 |
|---|---|---|---|
| 1 | ABOUT | 个人信息与履历 | `/about` |
| 2 | BUSINESS | 项目前期业务推导 | `/work/business` |
| 3 | BRAND SYSTEM | 母子品牌视觉系统 | `/work/brand-system` |
| 4 | PRODUCT LAUNCH | SOLIX 新品上市传播 | `/work/product-launch` |
| 5 | LAUNCH EVENT | IFA 发布会视觉与内容系统 | `/work/launch-event` |

第一版不接入最终正文和项目媒体。所有页面先使用有语义、有尺寸说明的占位内容，后续替换素材时不调整整体结构。

## 3. 首屏视觉结构

### 3.1 桌面端

严格继承 `24559704.png` 的空间关系：

- 顶部导航分布在品牌、Work/About、Contact、时间四个区域。
- 页面中央偏右放置 CRT 机器人主体。
- 机器人左侧显示当前项目名称、年份、摘要等信息。
- 左右两侧保留刻度导航。
- 页面底部放置五个项目按钮。
- 背景保持冷白至浅灰的低噪音渐变，不增加高饱和科技效果。

### 3.2 机器人实现

第一版复用现有 64 帧机器人序列图，不使用实时 Three.js 模型。

- Canvas 根据指针与机器人中心点的角度选择目标帧。
- 当前帧通过缓动向目标帧逼近，避免直接跳帧。
- Hero 只绘制当前所需帧，不拆分加载 64 张独立图片。
- 高 DPR 屏幕下限制合理的 Canvas 内部分辨率，兼顾清晰度和内存。
- `prefers-reduced-motion` 开启时停止持续跟随，保留静态正面帧。

### 3.3 移动端

移动端不是桌面页面的等比缩小，而是重新排布：

- 隐藏左右刻度、Contact 和时间等低优先级信息。
- 机器人居中并控制裁切范围。
- 项目入口改为横向卡片轮播。
- 提供拖动、前后箭头和分页点。
- 不使用 Hover；点击 `View` 打开案例。
- 可选使用轻量设备方向数据控制机器人，但不得阻塞主体验或触发权限弹窗。

## 4. 首页交互

### 4.1 桌面 Hover

Hover 任一项目入口时：

1. 更新当前项目 `activeProject`。
2. 项目按钮进入激活态。
3. 左侧项目信息切换，并执行短距离、低幅度的文字入场。
4. 机器人朝向对应按钮位置。
5. 左右刻度同步强调当前项目序号。

离开项目区后，保留最后一次预览状态，避免机器人和文字反复跳回默认值。

### 4.2 点击项目

点击项目后执行固定状态流程：

`idle → preview → zooming → open`

具体表现：

1. 锁定所选项目，屏蔽重复点击。
2. 机器人和 Hero 视觉向项目阅读焦点推进。
3. 顶部导航、刻度、底部入口降低透明度。
4. 案例全屏 Overlay 入场。
5. URL 更新为对应案例路由。

案例关闭时执行：

`open → closing → idle`

关闭完成后恢复打开前的项目、机器人方向、页面焦点和首页状态。

## 5. 案例路由与 Overlay

采用“全屏 Overlay + 独立 URL”的混合模式。

### 5.1 从首页打开

- 首页和机器人场景保留在下层，不重新挂载。
- Overlay 固定覆盖整个视口。
- 首页滚动被锁定，Overlay 内容区域独立滚动。
- URL 通过 Next.js 路由更新。

### 5.2 直接访问案例 URL

- 直接访问 `/about` 或任一 `/work/*` 时仍可正确显示案例。
- 页面先显示短暂的品牌加载遮罩，再呈现案例内容。
- 关闭案例后返回 `/`。

### 5.3 关闭方式

以下操作调用同一个关闭逻辑：

- 左上角关闭按钮。
- `Esc` 键。
- 浏览器返回键。
- 移动端系统返回操作。

关闭后必须恢复触发入口的键盘焦点。

## 6. 案例内容模板

### 6.1 About 模板

包含：

- 个人简介。
- 核心能力标签。
- 工作经历时间轴。
- 教育背景。
- 联系方式。

### 6.2 项目模板

BUSINESS 和三个案例共用项目模板，可按数据控制章节数量。

支持以下内容模块：

- 项目标题、角色、年份和摘要。
- 章节导航。
- 正文段落。
- 全宽主视觉。
- 双栏图像对比。
- 过程图或流程图。
- 视频容器。
- 数据结果。
- 下一案例入口。

### 6.3 占位内容

第一版占位块必须显示用途和推荐比例，例如：

- `HERO IMAGE / 16:9 / RECOMMENDED 2560×1440`
- `PROCESS DIAGRAM / 3:2 / RECOMMENDED 2400×1600`
- `VIDEO / 16:9 / MP4 OR WEBM`
- `RESULT METRICS / 4 ITEMS`

素材未提供时页面必须保持完整布局，不出现破图图标、内容塌陷或空白高度不明确的问题。

## 7. 工程架构

### 7.1 数据层

`ProjectRegistry` 统一维护：

- 项目 ID。
- 标签和标题。
- 路由。
- 简介和元信息。
- 首页预览数据。
- 封面与章节数据。

页面组件不硬编码五份重复内容。

### 7.2 组件边界

- `PortfolioShell`：全局页面结构、导航、时钟和响应式外壳。
- `SpritePortrait`：序列帧加载、Canvas 绘制和方向计算。
- `ProjectSelector`：桌面按钮、刻度和移动端轮播。
- `ProjectPreview`：当前项目标题和摘要。
- `CaseOverlay`：Overlay 生命周期、滚动锁定、焦点和返回行为。
- `CaseTemplate`：BUSINESS 与三个案例的统一模板。
- `AboutTemplate`：个人简介模板。
- `MediaPlaceholder`：带尺寸说明的占位媒体组件。

### 7.3 状态规则

核心状态：

- `activeProject`
- `overlayPhase`
- `overlayProject`
- `lastTrigger`
- `motionPreference`
- `viewportMode`

路由是可分享状态的来源，临时 Hover 状态不写入 URL。连续点击、快速返回和路由刷新不得产生两个 Overlay 或残留滚动锁。

## 8. 动效规范

- 页面加载遮罩：约 500–800ms，可被资源完成事件提前结束。
- Hover 反馈：120–240ms。
- 项目信息切换：约 300–450ms。
- Hero 推进：约 500–650ms。
- Overlay 入场：约 400–550ms。
- Overlay 关闭：约 250–400ms。
- 主要缓动采用克制的 ease-out 或低弹性 spring。
- 不使用持续发光、强烈弹跳、大幅视差或无功能装饰动画。

Reduced Motion 模式：

- 禁用序列帧持续跟随。
- Hero 推进替换为短淡入淡出。
- Overlay 保留必要的可理解状态变化，时长降至 100ms 左右。

## 9. 素材与清晰度

采用“高分辨率素材 + 响应式重排”，而不是把大屏页面整体缩小。

- 桌面关键 Hero 和封面建议提供 2560–3200px 宽的源文件。
- 位图优先转为 AVIF/WebP，并保留合理质量。
- 使用 `srcset` 或 Next Image 响应式尺寸，移动端不下载完整桌面大图。
- 不放大低分辨率原图。
- 视频提供封面，非首屏视频延迟加载。
- 序列帧源文件应满足 2× DPR 下的显示清晰度。

## 10. 性能策略

- 首屏只优先加载机器人序列图和当前项目封面。
- 其余项目封面在空闲时间或 Hover/触摸意图出现后预取。
- 案例正文图片默认懒加载。
- 视频接近视口后再加载，离开视口后暂停。
- 页面隐藏时停止非必要 Canvas 更新。
- Overlay 关闭后释放未使用的视频与监听器。

## 11. 响应式与验收

### 11.1 主要验收尺寸

大屏优先：

- 2560×1440
- 1920×1080
- 2048×852，作为 `24559704.png` 构图还原基准

向下兼容：

- 1440×900
- 1280×800
- 1024×1366
- 768×1024
- 430×932
- 390×844
- 375×812

### 11.2 验收内容

交互：

- 五个入口均可预览和打开。
- 桌面 Hover 状态稳定。
- 移动端轮播可拖动、可点击、分页状态正确。
- 关闭按钮、`Esc` 和返回键行为一致。
- 直接访问案例 URL 正常。

视觉：

- 2048×852 下与首屏基准图保持相同主构图。
- 大屏素材无明显模糊。
- 小屏无横向溢出、按钮遮挡或机器人错误裁切。
- Overlay 开关过程中无页面闪白或布局跳变。

无障碍：

- 所有交互可通过键盘完成。
- 焦点样式清晰。
- Overlay 具备正确的 Dialog 语义和焦点管理。
- Reduced Motion 生效。
- 文字与背景满足可读性要求。

## 12. 第一版不包含

- 最终案例正文、数据和媒体内容。
- 新的实时 3D 模型制作。
- CMS 或后台编辑系统。
- 多语言切换。
- 登录、评论或表单后台。
- 复杂音效和自动播放背景音乐。

这些能力不影响后续扩展，但不进入当前实施范围。
