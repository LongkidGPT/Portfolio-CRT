# R3 全帧交互正式首屏接入设计

## 目标

将已经在 `/kv-sync-test` 验证的 R3 全帧鼠标跟随方案接入正式桌面首屏。正式首页继续保留现有导航、项目文字、双侧标尺、五个项目按钮以及首页与子页面之间的缩放淡入淡出转场。

本轮只处理桌面端。移动端保持当前状态，不作为本轮验收范围。

## 素材与画面规则

- 唯一方向素材为 `KV首屏/首屏头部转动效果（R3）.mp4`。
- 使用已生成的 193 张 1470 × 630 WebP 完整帧；背景、人物和屏幕影像始终来自同一源帧。
- 正式首屏采用与测试页一致的 `contain` 规则完整显示 21:9 画面，不裁切、不抠图、不重新定位人物。
- 非 21:9 桌面视口出现的剩余区域使用当前首屏纸白背景承接，不拉伸视频。
- 正式首页不显示测试页的角度、帧号、加载量与错误量诊断面板。

## 组件边界

新增一个可复用的 R3 Canvas 渲染组件，负责：

1. 优先加载中性帧并预加载其余 192 帧。
2. 根据画布真实 `contain` 区域计算人物头部锚点。
3. 将桌面鼠标位置按画布四边归一化为 0—360°方向。
4. 使用已经校准的八方向关键帧、中心回正区域和缓动算法选择显示帧。
5. 接受可选的固定项目帧；固定帧存在时优先于自由鼠标跟随。
6. 在素材未加载或单帧失败时保留最近成功帧，避免首屏空白。

`/kv-sync-test` 与正式桌面首页共用这一渲染组件和方向映射纯函数。测试页继续添加诊断信息，正式首页只渲染 Canvas。宽度小于 768px 时继续使用现有 `SpritePortrait`，避免本轮桌面接入改变移动端行为。

## 正式首屏数据流

### 自由鼠标跟随

- 桌面精细指针在窗口移动时，正式首页把最新坐标交给 R3 渲染组件。
- 鼠标位于人物屏幕区域时显示中性帧 174。
- 鼠标离开中心区域后按当前八方向映射和缓动连续切换完整帧。
- `prefers-reduced-motion: reduce` 时固定显示中性帧，导航与按钮仍正常工作。

### 五个按钮

- 五个按钮继续使用现有项目数据、默认/悬停设计稿、文字轮转和路由。
- 悬停或键盘聚焦按钮时，首页传入该项目的固定 R3 帧，人物姿态锁定到对应方向。
- 离开按钮后清除固定帧，恢复自由鼠标跟随。
- 五个固定帧沿画面下半圈从左下到右下排列：`about` 124、`business` 134、`brand-system` 144、`product-launch` 150、`launch-event` 156。
- 不新增独立视频或屏幕播放层。

### 页面转场

- 点击按钮后继续使用现有 `zooming` 状态：导航、文字、标尺和按钮淡出，完整 R3 画面所在舞台放大、模糊并淡出，然后进入子页面。
- 子页面关闭时继续使用现有路由与返回动画，R3 首屏画面从放大透明状态恢复为正常尺寸与不透明状态。
- 不修改五个子页面的结构、路由和内容占位。

## 迁移方式

- 桌面端用共享 R3 渲染组件替换正式首页当前的 72 帧透明 `SpritePortrait` 渲染层；移动端继续使用旧组件。
- 正式首页的状态机、项目预览、按钮组件和路由计时保持原有接口。
- 将旧的项目固定帧表替换为 R3 对应帧表；旧 72 帧资源暂不删除，避免在本轮中引入不可逆清理。
- `/kv-sync-test` 保留为后续素材与方向校准工具。

## 测试与验收

### 自动测试

- 组件测试：正式首页加载 R3 中性帧，画布使用完整 1470 × 630 源画面。
- 单元测试：八方向、中心回正、五项目固定帧与 0°/360°环绕保持稳定。
- 浏览器测试：正式首页加载 193 帧且无错误；自由鼠标与五按钮悬停都能改变人物帧；点击项目和关闭子页面的转场仍可执行。

### 桌面人工验收

1. 21:9 视口完整显示 R3 画面，无裁切、拉伸或人物独立描边。
2. 鼠标在上、右上、右、右下、下、左下、左、左上以及人物屏幕中心移动时，页面命中当前已校准方向帧。
3. 五个按钮分别锁定对应姿态，离开后恢复自由跟随。
4. 首屏文字、标尺与按钮层级不被完整画面遮挡。
5. 首页进入子页面与子页面返回首页的缩放淡入淡出过程不回退。
6. Trancy 等浏览器扩展注入根节点属性时不出现 hydration 错误层。

## 已知素材边界

R3 原视频没有视觉上完全成立的“向右并同时向下”姿态。本轮沿用测试页已经确认的第 156 帧作为右下近似帧，不通过镜像、AI 补帧、局部抠图或独立屏幕播放伪造缺失姿态。若后续要求真实右下姿态，需要替换或补充源视频。
